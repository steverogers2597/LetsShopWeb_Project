The Full Execution Flow

🟢 STEP 1 — TestRunner.java is Triggered
UnknownYou click Run on TestRunner.java
         │
         ▼
TestNG sees it extends AbstractTestNGCucumberTests
TestNG hands control over to Cucumber


TestNG recognises TestRunner as a test class
The @CucumberOptions annotation tells Cucumber:

Where to find .feature files → src/test/resources/Features
Where to find step definitions → hooks and stepdefinitions packages
What reports to generate → pretty, HTML, JSON




🟢 STEP 2 — Cucumber Scans The Feature File
UnknownCucumber opens AccountRegistration.feature
         │
         ▼
Reads the Scenario line by line
         │
         ▼
Maps each Given / When / And / Then
to a matching @annotation in StepDefs


Cucumber finds your one scenario:
"Successfully register a new user on LetsShop"
It queues it up for execution


🟢 STEP 3 — CucumberHooks @Before Fires
UnknownBefore the Scenario starts
         │
         ▼
CucumberHooks.setUp() is called

Two things happen here:

BaseTest.initDriver() is called

Reads browser=chrome from config.properties
Launches ChromeDriver
Maximises the browser window
Sets implicit wait to 10 seconds
Opens the URL → https://rahulshettyacademy.com/client/#/auth/register


ExtentReportManager.createTest() is called

Creates a new test entry in the HTML report
Logs "▶ Starting: Successfully register a new user on LetsShop"




🟢 STEP 4 — Scenario Steps Execute One By One
UnknownEach step in the feature file runs in order
         │
         ▼
Cucumber matches the step text to a 
@Given / @When / @And method in StepDefs
         │
         ▼
StepDefs calls the relevant method
in AccountRegistrationPage.java
         │
         ▼
AccountRegistrationPage uses Selenium
WebDriver to interact with the browser

🟢 STEP 6 — CucumberHooks @After Fires
UnknownAfter the Scenario ends (pass or fail)
         │

🟢 STEP 7 — Reports Are Generated
UnknownThree reports written to disk:
         │

Open reports/TestReport.html in any browser to see the full visual report with logs
